# 论坛 MOD 下载

测试服务为 `https://api.fossic.org`，接口依据用户提供的 OpenAPI 3.1 文档和线上响应实现。当前公开的元数据接口可匿名访问，客户端没有预设认证方式。

## 已实现

- `Sspcl.Core/Store/Forum` 保存 API 数据模型、请求客户端和附件下载器；通用基础库不依赖论坛业务。
- `/mods?include_modding=false` 获取普通 MOD 索引；`original`、`translated`、`reposted` 共用 DTO，保留作者和译者字段。
- 三个 `/meta/*` 接口提供版本、分类和语言筛选；`/status` 保留未限定结构的 JSON 响应。
- 所有 API 和附件请求统一携带 `User-Agent: sspcl/0.98.1`；由请求层设置，版本读取 Core 项目的 `<Version>`，发布时同步更新该配置。
- VB/WPF 主程序下载页支持筛选、搜索、详情和显式选择发布包。不会依据 MOD 总版本号自动选择附件，因为一个条目的附件也可能是补丁、附加文件或前置库。
- 同时要求 `mod_allow_direct_download=true` 和有效的 HTTP(S) `download_url`。不满足条件时，只提供发布帖入口。
- 流式写入临时文件，支持进度与取消；检查 ZIP、RAR、7z 文件签名，不依赖论坛查询链接的文件后缀。网页、空内容和不完整响应不会交给安装器。
- 完整 MOD 使用现有安装器写入 MOD 池，不自动启用。没有 `mod_info.json` 的附件转为保存压缩包，用户按发布帖说明使用。安装和取消后清理临时文件。

数据中的 `mod_dependency_names` 与 `mod_conflict_names` 是名称，不能直接作为游戏 MOD ID 解析或自动安装。API 没有提供文件校验和；当前文件签名检查只识别格式，不能验证发布包来源完整性。`file_size`、时间戳保留为 Int64，时间单位未固化到显示逻辑。

## 数据层与缓存

`ForumCatalogRepository` 负责缓存、有效期、并发刷新与错误回退。页面只接收目录快照，不自行组织四个网络请求。缓存路径为 `%LOCALAPPDATA%\SSPCL\Cache\Forum\catalog-v1.json`。

- MOD 目录有效期 30 分钟；游戏版本、分类和语言独立缓存 24 小时。
- 打开商店先显示本地目录，再检查过期数据。缓存有效时不发送 HTTP 请求；过期时只请求需要更新的接口。
- 手动刷新强制更新 MOD 目录，仍保留元数据有效期；成功请求后有 1 分钟冷却。共享仓库实例串行合并多个打开或刷新操作。
- 请求失败保留最后成功的数据，2 分钟退避持久化到缓存。没有目录且首次请求失败时显示错误；元数据失败时从 MOD 数据生成可用筛选项。
- 写入使用临时文件和原子替换，包含缓存格式版本与 API 来源校验；损坏或不兼容缓存重新加载。磁盘写入失败仍可使用内存目录。
- 后台更新和下载时仍可搜索、筛选和下载其他发布包。任务捕获加入队列时的 MOD/发布包，不受后续目录选择影响。搜索、筛选、排序和刷新会保留仍有效的 MOD/发布包选择。
- 界面显示目录更新时间、缓存状态、结果数量和空结果提示，支持最新更新/名称排序与仅显示直下载筛选。下载仍需显式选择发布包。

API 尚未提供已确认的增量查询协议，因此过期目录会请求完整索引，当前没有假设 ETag 或增量字段。缓存可浏览不代表断网时能够下载远端文件。

## 并行下载与取消

- `ForumDownloadQueue` 最多允许 3 个下载同时传输，其余排队；下载结束、失败、超时和取消均归还名额。相同发布包在处理期间不可重复加入。
- 页面不再使用一个全局 busy 状态禁用目录。下载任务各自显示进度、状态和取消按钮；离开商店页面不会取消下载。
- 请求头等待最多 45 秒，读取正文每连续 60 秒无数据时报错。正文读取显式处理取消和关闭网络流，兼容不响应读取 CancellationToken 的流。
- 网络工作和取消在后台执行，进度在 UI 线程显示。MOD 池安装使用独立信号量串行处理，避免并发安装同 ID 的文件。
- 排队、下载和等待安装时可取消；已经开始安装或保存时禁用该项取消按钮，避免留下半安装状态。任务结束后可立即重新加入该发布包。
- 保存压缩包的路径在加入队列前选择。不是完整 MOD 的附件保留「保存附件」按钮，完成时不自动弹出对话框打断浏览；清除已结束任务会删除未保存的临时附件。
- 外层滚动容器将滚轮交给仍可滚动的内部列表，列表到达边缘时才滚动页面。

## 验证

无需安装额外测试库，契约检查通过一个独立控制台项目执行：

```powershell
# 离线：三种来源、可空字段、Int64 文件大小、元数据接口、HTTP 失败和取消、直连许可、格式识别、缓存清理、独立 MOD 池安装
dotnet run --project tests/Sspcl.Core.Forum.Tests -c Release

# 线上：读取索引和元数据
dotnet run --project tests/Sspcl.Core.Forum.Tests -c Release -- --live

# 线上：另外下载一个已确认的完整小 MOD 并安装到临时测试目录
dotnet run --project tests/Sspcl.Core.Forum.Tests -c Release -- --live-download
```

线上下载检查目前使用 `xsw_no_ff_mod` 的小型 ZIP 发布包。它依赖远端测试数据仍然存在，应按需手动执行；离线检查随 `eng/build.ps1` 执行。测试目录位于测试程序的 `bin` 下，不读取或改动实际游戏目录或用户 MOD 池。

缓存检查覆盖跨实例重开、有效缓存零请求、目录/元数据独立过期、重复刷新、离线回退、持久化退避、取消、损坏恢复、API 来源隔离、写入失败及临时文件清理。`--live` 同时验证真实数据写入磁盘后重开不发请求，并输出读取耗时。

并行检查覆盖卡流超时、不响应取消的流、3 项并发限制、排队/下载取消、重复任务阻止、释放名额、取消后重试与临时文件清理。页面检查同时验证活动任务不禁用浏览、搜索、结束后重新下载，以及嵌套列表实际滚轮事件。

Windows PowerShell 的独立 EXE 页面冒烟检查：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File eng/smoke-store.ps1 -Executable release/store-parallel/Sspcl.exe
```

此检查加载 EXE 的内嵌依赖和 WPF 资源，创建商店页面并验证目录、详情、搜索与筛选；不启动游戏、不下载 MOD，也不显示窗口。实际主窗口与保存对话框仍需人工验收。

## 导入已下载压缩包

商店顶部的「导入已下载压缩包」支持多选 ZIP、RAR、7z，逐个安装到 MOD 池；原压缩包保留，不请求论坛 API。ZIP 使用内置解压，RAR 和 7z 需要系统安装 7-Zip 或 WinRAR。安装与在线下载共用写入队列，在后台执行；同 ID 的旧版本按现有安装规则更新。导入后需到版本设置启用 MOD。没有 `mod_info.json` 的补丁或附加文件会提示按发布帖说明手动安装。

独立 EXE 检查覆盖入口存在、本地 ZIP 安装、原文件保留、缺少 MOD 元数据拒绝，以及本地任务与在线任务共存。

## MOD 启用状态

版本设置的勾选以 `enabled_mods.json` 中的 MOD ID 为准，文件夹存在不等于已启用。文件复制和清单写入在后台执行；同 ID 已安装时复用游戏中的文件，停用只更新清单。已存在的同 ID 重复副本会移至游戏目录的 `Sspcl/ModBackups`，避免游戏同时识别多个同 ID 目录。应用失败时保留原启用清单并显示错误。测试覆盖目录名不同的同 ID 复用、前置依赖、停用/重新启用、重复副本备份与连续写入。

## MOD 更新与内存概览

MOD 管理同时列出游戏目录和 MOD 池中的 MOD，每项提供「论坛更新」与「本地更新」。论坛更新复用目录缓存和三项并行下载队列，须手动选择发布包；未开放直下载的包可从发布帖下载后本地更新。更新服务按压缩包实际元数据核对 ID、游戏版本和声明的 JAR；目标游戏版本不同或元数据缺失时拒绝覆盖。适配版本中省略字母或 RC 的部分视为该主次版本的通用包（如 `0.98` 可适配 `0.98a-RC8`），明确的 RC 则须相同。

验证通过后完整替换 MOD 池及当前游戏中的旧目录，成功后删除旧版暂存目录，避免旧文件与新版混合；更新失败时恢复暂存旧版，启用清单保持不变。当前游戏运行时阻止更新。下载阶段可取消，替换阶段不可中途取消；本地源压缩包保留。RAR、7z 使用现有系统解压工具。已成功安装但旧目录因占用未能清理时会明确显示其路径。

概览显示当前 `vmparams` 的 Xmx/Xms，以及按该游戏目录匹配的 Java/Starsector 进程实际物理内存与私有内存，约每两秒刷新。进程不存在或无法读取时说明状态，不请求管理员权限。Xmx/Xms 是堆内存分配，进程实际占用还包含其他运行开销。
