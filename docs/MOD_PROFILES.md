# 共享 MOD 与启用方案

从 2026-10-12 起，启动器统一维护一份游戏与 `<游戏目录>/mods`。版本选择中的“版本”是玩家保存的 MOD 启用方案，不再是一份复制出来的游戏或 MOD 目录。

## 使用

1. 版本选择左侧“添加文件夹”指定统一维护的游戏目录。以后所有方案都使用该游戏及其 `mods`。
2. 版本设置 → MOD 管理：勾选想启用的 MOD，前置依赖自动补齐。勾选仅暂存，不立即修改启动清单或复制文件。
3. 点击“保存 MOD 启用方案”，填写名字，每次选择“添加新版本”或“替换现有版本”。替换目标可从已有方案中选择。同名新方案仍是独立清单。
4. 版本选择显示已保存的方案、启用数量、缺失 MOD 和清单目录。“使用此版本”选择下一次启动使用的方案；当前方案可直接编辑。
5. 启动前从所选清单生成共享 `mods/enabled_mods.json`，补齐前置；缺失 MOD、前置版本不足或同 ID 重复目录会阻止启动并说明原因。不会复制 MOD 文件。

只维护最新游戏，不再按游戏版本创建隔离实例，也不再以声明的游戏版本拦截 MOD 更新。论坛的版本字段作为信息展示，玩家仍需选择完整发布包。MOD 的 ID、文件完整性和前置依赖校验保留。

## 数据位置与迁移

- 路径与当前方案额外持久保存到 `%LOCALAPPDATA%/SSPCL/workspace.json`，更换启动器解压目录后仍读取同一配置。
- 配置 JSON 损坏时读取已有备份；恢复 MOD 入口与迁移共用安装锁，游戏运行期间不改变入口。选择已联接的 `mods` 时记住实际目标路径。
- MOD 管理顶部提供蓝色保存按钮、全选、全部取消、重新扫描和“选择 MOD 集文件夹”。列表使用虚拟化和普通复选框，勾选仅刷新发生变化的状态，不启动全列表动画。
- 默认可以直接使用游戏 `mods`；也可选择已有 MOD 集文件夹。外部文件夹通过无需管理员权限的 Windows 目录联接接入固定的游戏 `mods`，玩家不必改文件夹名字。首次替换原实体 `mods` 时，它保留为游戏目录内的 `mods-backup-*`；失败恢复原入口。选中目录自带的启用清单作为暂存选择，保存后成为方案。

- MOD 文件：统一游戏目录的 `mods`。论坛下载、本地压缩包导入和更新都写入此处。
- 方案：`%LOCALAPPDATA%/SSPCL/ModProfiles/<方案 ID>/profile.json`。ID 与显示名字分开，名字不会成为文件系统路径。替换时原清单备份为 `profile.json.bak`。
- 旧安装目录的启用清单首次转为方案；旧 MOD 池和旧游戏中的缺失 MOD 首次补入共享目录，同 ID 优先保留共享目录已有内容。旧源目录和文件不删除，不再用于后续启停操作。
- 迁移、切换及安装时需要游戏关闭；更换共享游戏目录前需结束下载任务。所有操作使用普通用户权限，不创建链接或系统服务。
- 内存、游戏 settings 和存档使用共享游戏目录；普通方案只隔离启用清单，不提供游戏文件或存档隔离。

## 整合包

原 `.sspack` / ZIP 清单包继续支持，禁止携带游戏本体和 MOD 文件。

- 导出按选择的已保存方案生成 MOD ID 清单，可选名字、版本信息、配置和存档。
- 导入生成新启用方案，不复制游戏或 MOD，也不要求本机安装包与分享包版本相同。MOD 版本字段不作为隔离依据；缺失 ID 单独下载。
- 可选配置与存档保存在方案的 `payload`。配置只在首次应用或包内配置内容变化时写入，重复启动保留玩家后续手动设置；不同方案仍使用共享游戏配置，不提供完整配置隔离。原文件备份到游戏 `Sspcl/ProfileBackups`；应用失败恢复已改文件和应用记录。
- 已存在的同名存档目录不会被覆盖，避免每次启动重置玩家进度。导入的存档目录仅首次写入共享存档目录，若同名目录已存在则保留本机存档。
