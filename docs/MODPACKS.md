# 清单整合包与版本选择

版本选择页左侧只提供「添加文件夹」「导入整合包」「导出整合包」。右侧列出已有游戏和导入得到的独立实例，以名称、游戏版本、缺失 MOD 和操作按钮呈现；移除原先选中文件夹的详细预览。

## 导出

选择来源游戏，再勾选要分享的内容：

- MOD 列表：已启用的真实 MOD ID、名称、版本。不能导出 MOD 目录、JAR、插件或游戏文件。
- setting 文件：`starsector-core/data/config/settings.json`，以及 `saves/common/config`、`saves/common/LunaSettings` 中支持的文本配置。
- 游戏版本：从核心 JAR 的版本常量中识别。
- 整合包名字：可省略。
- 存档：包含 `descriptor.xml` 的存档目录里的 XML、压缩 XML 和 JSON 文件。

所有选项可以独立关闭，包括全部关闭。`.sspack` 是 ZIP 格式，必需的 `pack.json` 只包含格式声明与所选元数据；不会包含游戏本体或 MOD 本身。未启用但在目录中存在的 MOD 不会进入清单。

## 导入

导入前分析包内容，展示可用选项，并选择本机基础游戏以及新实例目标路径。默认目标位于 `%LOCALAPPDATA%\SSPCL\Instances`，也可改为其他有写入权限的目录。

启用游戏版本选项时，基础游戏必须匹配清单版本。从本机基础游戏复制游戏文件到独立目录，使用所选配置、存档和名称；原游戏不改动。MOD 只从本机基础游戏的 mods 目录或 MOD 池匹配并复制，包含明确版本的清单要求版本一致。缺失条目保留在实例清单，并在右侧提示单独下载。

导入不会自动从论坛下载 MOD 或游戏。缺失 MOD 可能没有开放论坛直下载，需自行从商店或发布帖获取，再启用。新实例只启用匹配成功的 MOD；包含存档时，应先补齐清单中的缺失 MOD，再读取存档。

目标必须是基础游戏目录之外的新目录，不覆盖已有版本。导入在临时实例中进行，完成后才登记版本。取消或失败会清理本次临时目录。格式校验拒绝未知文件、MOD/游戏文件、重复路径及路径穿越，并限制解压内容大小。

## 下载游戏

右侧右下角加号沿用主页按钮外观，打开游戏下载入口。默认链接为用户提供的：

`https://cdn.fossic.cn/forum/202609/05/014446l82kxv7e16f63953.attach`

该链接实测返回 Windows EXE 安装包，约 250 MB。玩家可以修改链接和保存位置，查看进度、取消或重新下载。传输根据实际签名识别 EXE/ZIP/RAR/7z，并携带 `sspcl/0.98.1` User-Agent；沿用正文无数据超时与临时文件清理。程序只保存安装包，不自动执行安装程序。安装或解压完成后，用「添加文件夹」登记游戏。

## 验证

`eng/build.ps1` 的离线检查包含整合包所有选项、无 MOD 二进制导出、基础游戏保护、本机匹配、缺失清单、版本不匹配、禁止覆盖、非法路径、取消清理及游戏下载专用 EXE 支持。`eng/smoke-store.ps1` 在发布 EXE 的 .NET Framework 环境执行一次隔离导出/导入，验证侧栏、实例卡片、加号及五个可选项。

默认大安装包已检查响应头及前 8 字节；没有在开发机完整下载或运行该安装程序。下载传输通过受控样本验证，实际安装需由玩家按安装程序步骤完成。
